# gelm accessibility

This document records the accessibility decisions for stubbedev/gelm
(#13, #65): the semantic model every widget ships, the keyboard-first
guarantee, and — since #65 — the in-process AT-SPI bridge that serves
both to screen readers over D-Bus.

## Decision

**gelm speaks AT-SPI in-process, behind a build tag.** Default builds
carry none of it: the bridge (internal/atspi) and its application
wiring (app.ServeAccessibility) sit behind `//go:build atspi`, and
gelm's go.mod gains nothing (godbus was already a direct dependency
for the settings monitor). An application opts in with:

```go
app := app.NewApplication(sess)
if err := app.ServeAccessibility(atspi.Options{}); err != nil { ... }
```

The bridge serves what gelm always shipped:

1. **Semantic roles and state on every widget** — `widget.Role`,
   `widget.Describe`, and `widget.DescribeTree` expose role, name,
   value, text contents with caret and selection, checked state, and
   focusability as a plain Go API with no new dependencies.
2. **A keyboard-first guarantee, pinned by tests** — every interactive
   control in the showcase tree (`cmd/gelm-hello`) is reachable by Tab
   and activatable by Enter or Space, in both the widget unit tests and
   the showcase Tab-order test. This is the accessibility floor for
   toolkits on minimal Wayland setups: even without a screen reader,
   nothing is pointer-only.

## The bridge (#65)

`internal/atspi` serves the semantic model in the AT-SPI2 D-Bus shape.
It is snapshot-driven: a sampling pass runs on the application's loop
goroutine, rebuilds the tree of `widget.A11yState` snapshots keyed by
stable widget identity, and diffs it against the previous pass. Every
difference becomes an event; every handler answers from the published
snapshot, never touching widgets from the D-Bus goroutine.

- **Registration**: the accessibility bus is discovered through
  `org.a11y.Bus.GetAddress` on the session bus (which dbus-activates
  `at-spi-bus-launcher` on a real desktop); the bridge claims
  `org.a11y.atspi.gelm.p<pid>` (a bus-name element may not start with
  a digit), exports its root at
  `/org/a11y/atspi/accessible/root`, and handshakes with
  `org.a11y.atspi.Socket.Embed` — the modern registry probes the root
  of every new name itself, so an absent or older registry is a Debug
  note, never a failure.
- **Interfaces**: Accessible (roles, names, states, tree), Component
  (extents and hit testing — window-relative coordinates, a documented
  limitation: the compositor owns the window's screen position), Text
  (contents, caret, selections, the boundary and granularity readers
  over the model's rune offsets), Action (the click, performed through
  the widget's own Clicker path on the loop), Value (the ranged roles,
  with a working setter for sliders), and Application on the root —
  each with full `org.freedesktop.DBus.Properties` and Introspect
  support, the XML mirroring at-spi2-core's specs.
- **Events** (the minimal set): focus (`Event.Focus` plus
  `StateChanged focused`, the deprecated and modern forms),
  state-changed (checked, enabled, sensitive, editable),
  text-caret-moved, bounds-changed, and children-changed for tree
  updates. The diff is deterministic — focus first, then per-node
  state by ascending stable id.
- **Honest gaps, documented in code**: the semantic model is
  read-only, so the Text caret/selection setters and Component's
  GrabFocus decline (`false`) — gelm exposes no programmatic focus or
  caret API; per-glyph geometry (GetCharacterExtents and friends)
  reports nothing rather than guessing; component coordinates are
  window-relative. The AT-SPI Cache interface and the text-changed /
  property-change events are future work on the same snapshot-diff
  spine.
- **Cadence**: the default sampling interval is 100ms (`Options.Poll`
  tunes it; negative means the embedder drives `Refresh`). The walk is
  a DescribeTree over the window roots — cheap enough that it never
  matters in a profile.

### Verification

The wire contract is pinned by `go test -tags atspi
./internal/atspi/` (CI's `just atspi` step): a private dbus-daemon
plays the accessibility bus, a second connection plays the registry
(Socket.Embed) and the assistive technology — walking the served tree,
reading every interface, and receiving the event set as the scene
changes. accerciser/Orca verification against real at-spi2-core is a
manual, session-local exercise (run any demo client with the tag and
`ServeAccessibility` under a desktop with an a11y bus); the prototype
that informed this design already proved that path against real
at-spi2-core 2.60.

## The prototype, and what it proved

Before the bridge shipped, its feasibility was tested with a real
prototype (a few hundred lines of Go using `github.com/godbus/dbus/v5`,
kept out of the repository at the time), run against **real at-spi2-core
2.60** in a private dbus session. The mechanics all work:

- Discovering the accessibility bus: call
  `org.a11y.Bus.GetAddress` on the session bus (this dbus-activates
  `at-spi-bus-launcher` via the `org.a11y.Bus.service` file), then
  dial the returned address.
- Registering nothing: recent at-spi2 has **no `RegisterApplication`
  call** (confirmed absent in 2.60). The registry (`org.a11y.atspi.Registry`)
  watches the a11y bus for new unique names and probes
  `/org/a11y/atspi/accessible/root` on each. An application just
  exports objects and idles.
- Serving the tree: `org.a11y.atspi.Accessible`
  (`GetRole`/`GetRoleName`/`GetChildAtIndex`/`GetChildCount`/
  `GetState`/`GetAttributes`), `.Application`, `.Component`,
  `.Action`, `.Text`, plus `org.freedesktop.DBus.Properties` for
  Name/Description. godbus handles all of it; the atspi role and state
  enums are plain uint32 values.
- Consuming it back: a second Go connection played assistive tech,
  walked the tree by bus name, and read roles, states, action names,
  and text with caret offsets. The real registry stayed on the bus
  throughout.

That prototype is the checklist the shipped bridge implements; #65
closed the gap between "walkable" and "useful" with the snapshot-diff
event spine described above.

- `Role` mirrors the AT-SPI roles an external bridge would translate
  to: button, label, entry, text-area, slider, switch, check-box,
  progress-bar, scroll-area, list, menu, tab-list.
- `Describe(w)` snapshots role, name (tooltip text, else the wrapped
  or own label text), text contents, caret and selection as rune
  offsets, checked state, min/max/value/step, editable, multiline,
  enabled (the effective state, ancestors folded in), focusability,
  and bounds. A read-only text widget reports editable false; a
  disabled one reports enabled, editable, and focusable all false.
- `DescribeTree(root)` walks the tree in paint order — the same order
  focus traversal uses — so an integration can snapshot the whole
  window in one call.

### Keyboard-first guarantee

- `Button` fixes a real bug found by this work: its `KeyAction` had
  the wrong signature, so buttons never implemented `KeyActionHandler`
  and **Tab traversal silently skipped every button**. Buttons now
  activate on Enter and Space (the GTK activation pair).
- `Switch` and `CheckButton` implement `KeyActionHandler` +
  `RuneHandler`: Enter toggles, Space toggles.
- `Slider`, `Entry`, `TextArea`, `List`, `Menu`, and `Notebook` were
  already keyboard-operable; `KeyActionForSym` remains the single
  keysym→action map.
- Pinned by tests:
  - `widget/a11y_test.go` — roles and state snapshots for every
    widget; Enter/Space activation through the router.
  - `cmd/gelm-hello/a11y_test.go` — the Tab-order test over the real
    showcase tree: exactly six focusable controls in paint order
    (button, slider, switch, checkbox, entry, text area), a complete
    one-lap cycle with wrap, shift+Tab backwards, the TextArea Tab
    trap with its ctrl+Tab/shift+Tab escape, and Enter/Space/arrow
    activation of every focused control.

## Alternatives considered

**Out-of-process helper.** A small optional daemon
(`cmd/gelm-a11y`, its own module) reading `DescribeTree` snapshots
over a private socket and owning the godbus side. Rejected for the
shipped design: the in-process tag costs default builds nothing,
keeps widget identity trivial (the bridge sees the live tree, not a
serialized snapshot), and needs no inter-process protocol. The helper
remains the fallback if a dependency-free go.mod ever matters more
than it does today (godbus was already direct for the settings
monitor).

**Rely on the compositor.** Wayland has no merged accessibility
protocol yet; existing projects solve narrow cases only. Nothing to
integrate today; worth re-checking as the protocol landscape moves.

## Revisit triggers

- An AT user or distro runs the tagged bridge against Orca or
  accerciser in a real deployment — their findings shape the next
  event (Cache, text-changed, property-change) or interface
  (Selection, Table) on the snapshot-diff spine.
- Wayland grows a compositor-level a11y protocol.
